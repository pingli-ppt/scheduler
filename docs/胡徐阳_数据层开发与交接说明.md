## 2. 李萍现在可以怎么接

可以从这里导入五个函数：

```python
from data.repository import (
    load_foods,
    load_child,
    load_history,
    load_daily_intake,
    save_record,
)
```

如果已经从 `data.loader` 导入，也可以继续用，调用的是同一套函数。

| 函数 | 做什么、返回什么 |
|---|---|
| `load_foods()` | 返回全部食物的 `list[dict]`，键与食物 CSV 列名一致；月份为 `list[int]` |
| `load_child(child_id)` | 返回指定儿童档案的 `dict`；过敏类别为 `list[str]` |
| `load_history(child_id)` | 返回 `list[dict]`，包含 `food_id`、`date`、`status`，按日期升序 |
| `load_daily_intake(child_id)` | 返回 `list[dict]`，包含 `date`、`categories`、`meal_count`、`is_breastfed`、`milk_feeds`，按日期升序；类别为 `list[str]` |
| `save_record(child_id, food_id, date, status, note)` | 保存记录，返回 `None` |

出生日期、开始辅食的日期和记录日期都返回 `datetime.date`。
食物记录状态按原约定使用 `planned`、`passed`、`reaction`、`refused`。

李萍可以继续按这几个接口调用正式食物数据。`load_foods()` 现在会额外返回
`auto_recommend`；算法已经使用该字段排除不参与自动推荐的食物。

默认数据库现在没有自动生成儿童档案。测试里的 `C001`、`C002` 只在临时数据库中，
不能直接当成默认数据库里已有的档案来查。对接时用模拟儿童档案即可，不需要找真实孩子。

## 3. 正式食物数据接入情况

按组长的计划，9/23 先交约 30 种，9/27 累计约 60 种，9/28 累计约 100 种。

100 种食物已经汇总到 `data/foods.csv`。食物表增加 `auto_recommend` 字段：`1` 表示
可以参与自动推荐，`0` 表示保留在食物库中但不进入候选池。导入程序会校验并保存该字段。

字段和录入规范仍按组长文件和吴琦的样板来。我这边的导入检查不代替吴琦负责的
录入规范和校验工作。食物编号要保持一致，避免已有记录对应到别的食物。

导入工具目前要注意两点：

- 相同编号会更新整条记录，留空也会覆盖旧值。组长要求的“只更新改动部分”还要完善，
  目前不能算导入工具的最终版。
- 本次 CSV 没有的食物不会自动从数据库删除；不要以为少传几行就能删掉旧数据。

数据层字段、类型和算法调用已经接通。API、页面、埋点、导出继续按后面的计划完善。

## 4. 压缩包里的文件和运行方式

| 文件 | 用途 |
|---|---|
| `data/__init__.py` | 让 Python 按包导入 |
| `data/database.py` | SQLite 连接和建表 |
| `data/repository.py` | 五个数据函数 |
| `data/loader.py` | 保留原有导入入口 |
| `data/import_foods.py` | 导入食物 CSV |
| `data/validate.py` | 数据解析和导入时的格式检查 |
| `data/foods.csv` | 100 种正式食物，包含新增的 `auto_recommend` 字段 |
| `docs/` 中的本说明 | 本次交接说明 |

在项目根目录运行，使用 Python 3.10 或更高版本：

```powershell
python -m data.database
python -m data.import_foods
```

默认数据库在 `data/guochu.sqlite3`，不会自动添加食物或儿童。数据库文件不上传 GitHub；
下载代码后，需要在本地生成数据库并导入食物数据。
